# 回放手勢實作與下一步（0.2.3）

## 使用方式

練習頁五指仍保存並回看，比讚仍開始／停止整段錄影。回放頁新增：

| 手勢 | 動作 |
| --- | --- |
| 拇指朝下 | 提早返回延遲練習 |
| 食指朝上 | 加快一檔，0.25× → 0.5× → 1× |
| V 手勢 | 放慢一檔，1× → 0.5× → 0.25× |
| 五指張開 | 同一段從頭重播，保留速度與鏡像 |

保持回放手勢約 0.6 秒，比完放下手約 0.3 秒再比下一次。進入回放的同一張掌不會直接重播；同一姿勢持續保持不會一直重播或加速。速度上下限不循環，重播不另存一份影片。手動控制增加「重播」，仍可用觸控補救。

第一次未操作的回放播完後，保留最後畫格兩秒並顯示倒數，供五指重播；之後自動返回。改速、重播、暫停、拖曳、鏡像或開啟說明視為主動研究，留在回放直到明確返回。手勢說明收進按鈕，不常駐遮住影片。

## 技術責任與保護

- GestureEngine 保留一個 MediaPipe 模型、同一即時相機來源，增加結果所對應的畫面版本；辨識結果與排入主執行緒的指令都要重新核對。丟幀對照表最多 64 筆，避免 LIVE_STREAM 省略 callback 時累積。
- GestureCommandGate 共用觸發路由。保存／比讚穩定 350 ms、冷卻 3 秒；回放動作穩定 600 ms、冷卻 800 ms；每次場景切換與觸發要求穩定中立 300 ms。低信心的同一控制姿勢不當作放手。張掌沿用裝置上調整過的 0.55，其他初始門檻 0.70。
- PlaybackSessionController 共用速度、重播與研究互動。重播 seekTo(0, 0) 從第一個 media item 開始，保留回放速度與鏡像；速度不作用於延遲播放器，也不再觸發影片保存。播放器事件同步速度 UI。
- ReplayReturnPolicy 用單調時間管理兩秒停留。互動清除倒數並鎖定研究停留；前背景切換不延用舊 deadline；所有播放器操作在主執行緒。
- PracticeCameraLayout 在導航之外保留唯一 attached PreviewView；LiveScreen 只回報小窗位置。回放時 host 透明、仍供應 Surface，避免離開 LiveScreen 後手勢失去即時相機畫格；不另開相機或模型。
- 返回仍等待匯出作業完成才清理回放 snapshot；不中斷原有整段錄影、單箭保存或失敗重試。未建立影片時不宣稱重播成功，使用手動返回與重試補救。

## 驗證界線

JVM 新增場景、門檻、保持、單幀消失、低信心、放手、冷卻、舊結果與倒數競態測試。原生新增實際 Media3 跨 media item 重播、速度邊界、觸控／模擬手勢事件一致性與即時相機跨頁測試。既有錄影、匯出、前背景、橫向與暖機測試仍執行。

模擬手勢事件驗證路由與播放結果，不能證明真實手指／護具／逆光在腳架距離下的辨識效果。相機測試使用 API 34 的模擬前鏡頭，也不是使用者 Pixel 實機驗收。CI 結果與 APK 連結完成後補入。

版本 0.2.3／versionCode 6，套件與修正版 3 相同。CI 維持原簽章並核對憑證，支援直接覆蓋更新。

## 下一步安排

1. **實機確認本版控制**：依使用者腳架站位各比四種回放手勢；確認五指跨頁只保存一次、比讚不被新手勢誤判、速度／重播正確，且錄影與保存持續。以實際 score、成功率與自然動作誤觸決定是否調門檻，保留手動入口。
2. **優先做安全返回緩衝原型**：目前 skipReplay 仍清除 delay 緩衝並重新暖機，這是保留既有黑屏復原機制的選擇。原型需有效來源時間、片段版本／引用保護、過期 callback 與首畫格驗證；不直接拿掉 reset 或恢復暫停前的舊位置。目標是正常回放返回時利用現有緩衝，只等首畫格；不足或來源變更仍真實暖機。先量測再作 APK 行為變更，不宣稱零等待。
3. **提前驗證多裝置一拍一看**：兩台 Android 同 Wi-Fi／熱點，限定傳現有已完成片段與一個明確控制指令。核對延遲、斷線、唯一手勢辨識端與不重複執行；正式同步保存／原檔收集仍依 PM／SA 的來源時間與事件基礎安排。

語音、A–B 循環、放大、逐格等仍按里程碑分開，這次不混入回放手勢 APK。
