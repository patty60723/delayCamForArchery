# 回放快速返回：與現行版並存測試

狀態：0.2.4-fast-return-test 原型。不是現行版的自動升級；實機回饋前不切換正式預設。

## 安裝與對照

| 項目 | 現行 0.2.3 | 本次測試版 |
|---|---|---|
| App 名稱 | 射箭 Delay Camera 修正版 3 | 射箭 Delay 快速返回測試 |
| 套件 | com.archery.delaycam.delayfix3 | com.archery.delaycam.fastresume |
| 回放返回 | 清空緩衝，重新暖機 | 有效緩衝快速接回，失效則暖機 |
| 設定與相機權限 | 沿用現有資料 | 獨立資料，需要首次授權及設定 |

下載測試 APK 後直接安裝，保留修正版 3。兩者分別開啟使用，不同時搶用相機。測試版不會自動複製現行版設定或私有資料；使用手機相簿查看已匯出的影片。第一次啟動仍需暖機，不把它當作快速返回失敗。

建議兩個 App 都先設延遲 5 秒、回溯 8 秒、回放 0.5×。依序各測：

1. 暖機完成後保存並回看，用按鈕或拇指朝下提早返回，觀察恢復動態畫面的等待時間。
2. 完整看完一段，不操作，等兩秒倒數自動返回。
3. 回放中調至 0.25×、重播數次，再返回，確認沒有接回離開前的舊畫面。
4. 開啟全程錄影後重複上述流程，最後停止錄影，在相簿確認返回前後都有影片。
5. 在回放時滑到桌面，再回來並返回練習。此情況應安全重新暖機；原有背景停止／保存錄影政策仍適用。
6. 連續做 10 次回放與返回，觀察黑屏、停格、暖機頻率與發熱。記錄是哪個 App、延遲設定、使用的返回方式，以及有沒有切到桌面。

成功標準是正常回放返回免重新等待整段延遲時間，且顯示現在往前設定秒數附近的影像。仍需播放器準備及首畫格時間，不承諾零毫秒、固定 FPS 或逐格精準來源時間。

## 實作

### 編譯隔離

`-PfastResumeTrial=true` 啟用 `BuildConfig.FAST_RESUME_TRIAL`，產生獨立 `.fastresume` 套件與名稱；不加此參數時快速返回關閉，debug 套件仍是 `.delayfix3`。CI 產出測試版並核對 APK 身份及既有簽章，原生測試工作同時安裝兩種套件驗證並存。

### 暫存檔所有權

`ImmutableSegmentStore` 為每個前景拍攝工作階段分配唯一檔名，不重用覆寫檔案。保留數沿用原有緩衝大小；過期且沒有讀取者的片段刪除。播放清單、等待加入的片段、單箭快照複製和全程錄影佇列各自取得 lease；最後一個讀取者釋放後才可回收。跨工作階段、未完成或已缺失的檔案無法取得 lease。

編碼仍用既有單一 MediaCodec 與 CameraX 分析影格，不增加相機或第二個編碼器。新增紀錄樣本 PTS 的跨度，用來核對片段牆鐘時間與估算 seek 位置。對外匯出仍經既有快照、MediaStore 與錄影狀態機。

### 返回流程

1. 進入回放前記住緩衝世代，清除延遲播放器及其舊 Handler callbacks，釋放該播放器的 lease；保留來源緩衝並繼續拍攝及錄影。
2. 手勢返回、按鈕返回和未操作回放結束都經 `onReplayFinished()`。
3. 同一前景／設定世代內，由 `FastResumePlan` 找到 `現在 - 延遲` 所在的已完成片段，核對來源連續性、有效時間與檔案所有權。
4. 先取得新清單 lease，再建立新 Media3 清單並定位至目標片段內的位置；後續完成片段依順序銜接。播放過的清單項目移除後釋放 lease。
5. 回到既有 LIVE 畫面，使用原本的「等待第一個延遲畫格」提示；實際 `onRenderedFirstFrame` 才清掉準備提示。

### 安全退回暖機

下列情況使用原本 `resetDelayedPlayback()`，不強行播放不確定的資料：

- 背景／前景切換、延遲秒數變更，或既有播放器錯誤導致世代改變。
- 找不到目標，來源過舊、重疊、缺段、檔案缺失或來自不同拍攝階段。
- 片段長度不在 100–5000 ms、相鄰間隔超過 150 ms，或媒體跨度與牆鐘跨度相差超過 500 ms。
- 目標之後不足 500 ms 的已完成影片。1–2 秒等短延遲尤其可能遇到未完成片段；仍可使用原本暖機播放。
- 快速返回後 5 秒未呈現首畫格，或後續來源位置相對設定延遲偏移超過 3 秒。
- 原有播放停滯監測或 Media3 錯誤回呼觸發。

快速返回使用來源時間定位；舊版首次暖機以「片段完成時間＋延遲」排程，因此兩者實際畫面延遲可能相差約一個片段。拍攝時間目前以編碼輸出時間估算，尚未改成攝影機硬體逐影格時間映射；需在實機比較實際延遲與接段品質。

## 驗證與限制

新增 JVM 測試涵蓋目標選擇、缺段／時間異常、長時間檔案輪替、同時播放與匯出的保護及釋放；原生測試使用實際 H.264、Media3 解碼、ViewModel 返回流程、背景／設定失效及單一編碼器輸出。原有手勢、錄影保存、橫向版面與相機連接測試也需通過。

CI 結果與 APK 連結於完成後記錄。Pixel 的發熱、連續練習、真人手勢辨識與實際恢復時間仍以使用者對照測試為準。未加入多裝置串流；下一步依本次回饋修正，再做熱點＋瀏覽器觀看原型。
