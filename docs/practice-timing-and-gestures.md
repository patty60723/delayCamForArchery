# 功能使用時機與手勢互動原則

制定日期：2026-10-12。依使用者指示，所有提案須同時考量功能在當下或事後使用；當下功能應評估手勢，盡量不干擾射箭節奏。

此原則納入 [PM 交付關卡](pm-delivery-roadmap.md) 與 [SA 指令／狀態設計](sa-system-design.md)，後續實作以兩份文件整合安排。

本文件是後續功能的規劃標準。現行 APK 的手勢仍是張掌保存並回看、比讚切換全段錄影；以下預設調整、語音流程及多裝置手勢路由尚未實作。

## 1. 依使用時機安排操作

| 時機 | 使用者在做什麼 | 適合的操作 |
| --- | --- | --- |
| 練習前 | 架手機、選延遲與構圖、設定今天重點 | 可觸控設定，記住偏好；手勢可協助站定位後確認 |
| 放箭後當下 | 收勢、看剛才動作、準備下一箭 | 自動顯示與暫存；需要保留時，一次可選手勢完成 |
| 組間 | 已完成一組、決定是否重看或調整 | 可進入回放、挑片或簡短回顧；主要動作仍提供手勢入口 |
| 事後 | 研究細節、比較、整理與分享 | 使用觸控做精細定位、逐格、裁切與填寫，不要求練習當下完成 |

功能可以橫跨多個時機。當下的任務通常是留下影片、標記或感受；詳細解讀可稍後進行，不能把整套分析流程放進每一箭之間。

## 2. 當下互動的預設

1. 延遲播放與啟用的暫存自動進行，不要求每箭操作。
2. 想留下一箭時才比手勢；一次確認後即可繼續，保存與錄影背景工作不要求使用者等待完成畫面。
3. 依最新回放手勢需求，練習頁張掌沿用現行「保存並回看」；「只保存」提供可選偏好，選擇應保持清楚並記住，不默默改掉已有使用者的流程。回放張掌可規劃為重播同一段，見 [回放控制提案](replay-gesture-control-proposal.md)。
4. 語音備註若在練習前啟用，可讓同一次保存手勢開啟短錄音，自動結束。錄音時不要求按開始、按停止或輸入文字，也不強制進入回放。
5. 日誌、階段時間標記、細部裁切與自評放在組間／事後；略過時能繼續下一箭。
6. 成功、處理中或失敗用簡短可讀的畫面提示，提示音可選。暖機仍保留剩餘秒數；一般保存不遮住影片或要求關閉對話框。

保存可以非同步完成，但提示必須區分「已接收指令」「保存中」「已保存」「失敗」。已收到手勢不等於檔案已成功保存；失敗的重試入口保留到組間處理。

## 3. 五個單機提案的安排

| 功能 | 使用時機 | 當下與手勢安排 | 組間／事後安排 |
| --- | --- | --- | --- |
| 構圖助手 | 練習前 | 架好站定位後可用手勢確認；選角度、參考圖與透明度先觸控設定 | 需要改構圖時放在組間 |
| 語音動作備註 | 當下留下感受、事後研究 | 先啟用偏好，張掌保存時一併開短錄音；自動結束，維持延遲與錄影 | 播放、重錄、刪除與文字修正放到稍後 |
| 最近片段暫存 | 當下自動保留、組間挑選 | 啟用後免操作；張掌可直接保存目前想保留的動作 | 時間軸挑選、裁切與批次保存在組間／事後 |
| 動作節奏分析 | 主要是事後 | 當下只留下影片，不要求拉弓或定位時比手勢打點 | 手動標記拉弓／定位／離弦，計算與比較 |
| 練習重點與回顧 | 練習前選重點、組間／事後回顧 | 目標自動附在保存影片；無須每箭作自評手勢 | 自評、代表影片與下次重點可稍後填，允許跳過 |

## 4. 既有研究工具與多裝置也採同一原則

- 長錄影重點標記：可隨當次保存指令記錄來源時間；不要把既有比讚另解讀成「這箭很好」，以免與停止錄影衝突。
- 局部循環、放大與逐格：屬主動研究。使用者明確進入回看後可操作，正常延遲觀看不自動轉入循環或要求找起終點。
- 多裝置一拍一看：在一個指定拍攝端辨識手勢，再由主要控制者執行一次。觀看端預設不啟動鏡頭；如果拍攝角度看不到手，需改選可辨識的拍攝端或保留手動入口。
- 多角度收集：當下各自保存，收集放在組間／結束；手勢可以提出「結束這組」，實際保存與收齊結果仍需核對。
- 教練回饋：教練回放獨立運作，射手在放箭後或組間自行查看，提示不強制切換射手畫面。

## 5. 手勢設計與可行性

先維持使用者熟悉的兩個核心手勢：張掌保存、比讚開始／停止錄影。張掌完成的保存結果可按事先偏好附上標記或語音，但同一次指令只產生一份保存事件，不能同時啟動幾個互相競爭的流程。

不為每個新功能新增一個必記手勢，也不優先採用連續組合手勢。使用者明確提出主動回看的返回、加快／放慢及重播，故在 REPLAY 驗證拇指朝下、食指朝上、V 手勢與張掌重播，LIVE 不接受新增播放控制；比讚保留錄影。手勢、按鈕與文字提示要指向同一個明確動作，不增加每箭必要操作。

程式目前使用 MediaPipe 的單手辨識，接受張掌與比讚兩個類別，並有穩定時間、冷卻與鬆手後重新啟用。官方模型另有 Victory 等類別，能作候選，不代表在射箭距離、護具或戶外環境中已可可靠使用。[MediaPipe 官方手勢文件](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer)。

當下使用應在收勢後完成可選手勢，練習本身不依賴每箭一定有指令。目前程式沒有自動辨識拉弓／定位階段；不能宣稱已在射箭中自動停用辨識。保護靠明確畫面狀態、門檻、保持只觸發一次、鬆手重新啟用及忙碌時抑制重複指令，並用真實動作檢查誤觸。

切換進出架機／回放等模式時，需要等待原本手勢解除後再接受新的指令，避免同一隻保持張開的手在兩個頁面各觸發一次。相簿、設定與已結束練習的頁面不接收射箭手勢。

## 6. 語音與保存的時間關係

手勢接受後若開啟短錄音，不能等較慢的影片匯出完成才開始錄音，讓使用者錯過當下感受。先給本次事件與待保存片段固定識別，音訊關聯該事件；影片保存完成後再接成完整項目。若影片失敗，保留本次備註與待重試關聯，不改掛到下一支影片。

錄音偏好與麥克風授權在練習前完成，預設關閉。短錄音長度可先用約 5 秒作驗證起點；顯示小提示並自動結束，不影響下一箭或全段錄影。沒想錄語音時可以繼續練習，事後管理該備註，不強制當下填寫、刪除或確認。

保存／標記引用使用者想保留的來源影像時間；使用者正在看延遲畫面時，不能直接用手勢被辨識的牆鐘時間作影片內的標記。多裝置時還須依主要觀看端的來源時間映射，避免辨識端與觀看端各存不同一箭。

## 7. 每項提案的必要評估欄位與驗收

未來每項提案都列出：主要使用時機、是否能免操作、手勢是否合適及看得到手、是否跳頁、是否影響延遲／錄影、成功與失敗如何提示，以及稍後如何補救。

評估成效以走到手機的次數、每箭必須操作的次數、手勢一次觸發成功率、誤觸次數、是否需要等待保存，以及是否打斷下一箭為準。不能只以「有加手勢」判定流程已改善。

建議驗收：保持同一張掌只執行一次；持弓、拉弓與收勢的自然動作不反覆切換錄影；保存或錄音期間可繼續延遲觀看與全段錄影；手勢失效仍能用手動入口；單箭與語音配對正確；沒有強制自評或自動跳出教學。距離、護具、逆光與不同站位都需實機測試。以上均為規劃條件，尚未驗證。
