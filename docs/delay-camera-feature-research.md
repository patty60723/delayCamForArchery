# 延遲攝影機功能與設定研究：單人射箭練習

研究日期：2026-10-11；2026-10-12 新增使用者提出的多裝置需求。程式基準：目前已合併的 0.2.1，合併 commit `d7653b47255a82f09a9ab8468d6f8ffbb715cf60`。

使用情境：自己架手機，放箭後立即看動作；同時會錄影，事後研究。以下分清楚目前功能、官方產品文件中的功能，以及針對這個情境提出的產品建議。優先順序與預設值是本次分析，不是競品的設定，也不是已實作功能。

研究方法：閱讀延遲攝影與動作分析產品的官方網站、開發者商店介紹及 Android 官方技術文件，再核對目前程式。沒有實際操作競品、量測手機效能或做使用者訪談；不把競品宣傳的效果當成已驗證的訓練成效。

## 1. 建議方向

先補「能看清同一箭」和「能從長片找回這一箭」，再加拍攝控制與遙控。這比繼續增加播放速度選項，更符合目前的練習方式。

第一批建議：A–B 局部循環、回放放大、長錄影重點標記，以及可收藏的單箭。逐格同樣重要，但應以真實影格與時間戳實作，不能把固定毫秒跳轉包裝成精準逐格。

高 fps、雙片比較、聲音觸發和外接鏡頭可以增加能力，但應分批做。既有黑屏與重啟修正依賴穩定的單一影像管線，新增拍攝功能必須保留這個設計原則。

2026-10-12：使用者已提出多裝置需求，將其納入規劃。建議先驗證「一台 Android 拍攝＋另一台 Android 看延遲畫面及遙控」，再增加雙角度；iPad／電腦觀看端另評估瀏覽器或原生版本。詳見 [多裝置可行性與功能規劃](multi-device-feasibility.md)。

同日追加兩個多裝置提案：「每組結束收集多角度影片」與「教練旁看與時間點註解」。前者以各自拍攝、每組結束後收集為流程，適合目前的單人練習；後者以獨立回看與回饋為流程，適合有協助者的情境。詳細功能、可行性與驗收見多裝置文件第 12 節。

依使用者要求，再追加五個單機功能提案：拍攝構圖助手、一箭一段語音動作備註、最近片段暫存與挑選保存、射箭動作節奏分析，以及練習重點與每組回顧。詳見 [五個單機功能提案](single-device-feature-proposals.md)，包含用途、最小版本、工程條件與優先順序。

使用者進一步指定：每項功能要分清楚練習前、當下、組間或事後，當下應評估手勢，盡量不干擾射箭節奏。此原則適用所有既有與後續提案；建議張掌保存預設留在延遲畫面，精細分析稍後處理。具體時機、手勢與驗收見 [功能使用時機與手勢互動原則](practice-timing-and-gestures.md)。

整體交付順序已依使用者要求重新整合為 [PM 交付安排](pm-delivery-roadmap.md)，系統模組、資料與執行工作包見 [SA 系統分析](sa-system-design.md)。本文件保留功能研究依據，後續版本排序以 PM 文件為準。

## 3. 目前已有的功能

- 延遲 1～30 秒，預設 5 秒；回溯設定 3～30 秒，預設 8 秒。
- 1×／0.5×／0.25× 回放、播放／暫停、時間軸、前後 5 秒與鏡像。
- 單箭「存檔並回看」或「只保存」，整段錄影與錄影狀態。
- 張掌保存、比讚開始／停止錄影，並有手動入口。
- 水平／垂直參考線、即時小視窗及收起操作；橫向影片與側邊操作區。
- 準備倒數、相簿、刪除確認、系統分享。
- 切到桌面會停止並保存當前錄影；回來重新準備延遲畫面。

目前尚未有：精準逐格、A–B 循環、可持久保存的時間點標記、影片收藏與備註、練習分組、裁切、回放局部放大、後鏡頭選擇、使用者可選的畫質／fps、遙控或聲音觸發。

「慣用手」目前只決定即時小視窗在左上或右上，沒有判定射箭姿勢；建議改名為「即時視窗位置」。小視窗顯示與影片鏡像目前主要是畫面狀態，可以補上跨次開啟的偏好保存。

## 4. 建議加入的功能與優先順序

優先是直接改善目前兩種核心用途；其次是讓拍攝或操作更方便；後續是需要更多裝置、辨識或效能驗證的能力。

| 順序 | 功能 | 射箭使用例子 | 最小可用版本與注意點 |
| --- | --- | --- | --- |
| 優先 | A–B 局部循環 | 只看放箭前後 2～3 秒，不斷回看拉弓手與持弓手 | 暫停後設定起終點，循環直到使用者返回；不能自動打斷研究 |
| 優先 | 回放局部放大、平移 | 放大勾弦手、臉部定位或手肘 | 雙指縮放，提供一鍵還原；只改觀看，不破壞原始影片 |
| 優先 | 長錄影重點標記 | 剛才那箭感覺特別好，先做記號，晚上直接跳到 | 「標記目前看到的動作」；保存對應來源影像的時間，不用按下時的牆鐘時間 |
| 優先 | 收藏、簡短備註與練習分組 | 保存「延伸順暢」的一箭，與上週比較 | 日期／時段分組、收藏、少量常用標籤；單箭與整段錄影清楚區分 |
| 優先，需媒體驗證 | 精準逐格 | 找到離弦前一格與離弦後一格 | 暫停時前／後一格；依實際解碼影格與 PTS 導航，涵蓋片段交界 |
| 其次 | 區段裁切與截圖分享 | 將長片中的一箭或一個定位畫面交給教練 | 保留原片、匯出選定區段；截圖可選含不含參考線 |
| 其次 | 拍攝預設與個人設定檔 | 戶外練習與室內研究使用不同延遲、線條與鏡頭 | 命名並保存設定，直接進入上次使用的組合，不新增每次開啟必答的模式選單 |
| 其次 | 曝光／對焦鎖定、鏡頭選擇 | 背景有人經過時畫面不要忽亮忽暗；需要時用後鏡頭錄較細的動作 | 點按取景與鎖定；只顯示該鏡頭支援的控制，切鏡頭明示重新準備 |
| 其次 | 藍牙按鍵／音量鍵遙控 | 放下弓後按遙控器保存或標記，不必走到手機 | 先支援鍵盤／媒體按鍵映射；實測常見配件，避免一次按鍵重複觸發 |
| 其次，保存架構工作 | 定期完成錄影片段與中斷復原 | 長練習中 App 被系統結束，重開後找回已完成的錄影片段 | 保存錄影專用片段與索引，不能依賴會覆寫的延遲緩衝；不承諾救回尚未完成的尾段 |
| 後續 | 兩片同步比較 | 本週與上週，或較好與較差的一箭對照 | 各選離弦時間作同步點，連動播放／逐格；優先橫向相簿研究畫面 |
| 後續 | 手動畫線、角度與時間量測 | 標出手肘軌跡，比較定位至離弦的時間 | 先提供線、箭頭與時間；角度明示為拍攝平面中的角度，不自動判定姿勢正確 |
| 後續 | 每箭自動慢動作重播 | 做完一箭就播放兩次，再準備下一箭 | 先用手動或遙控觸發，設定重播次數；固定節奏不一定適合不同拉弓時間 |
| 後續，先實驗 | 聲音／離弦事件觸發 | 聽到自己的放箭聲，自動標記或取出單箭 | 相鄰射手和環境聲會造成誤觸；先標記、允許撤銷，避免自動停止全段錄影 |
| 後續，需實機驗證 | 高 fps 拍攝 | 增加放箭前後可檢查的影格數 | 先驗證 60 fps；120 fps 作獨立能力評估，不只是新增設定數字 |
| 使用者已提出需求，先做原型 | 多裝置觀看、遙控與雙角度擴充 | 手機架在側面拍攝，另一台放在容易看見的位置；後續正面／側面同箭回看 | 第一階段 1 拍攝端＋1 觀看控制端、區網連線、原檔在拍攝端；雙鏡頭、跨平台與外接攝影機分別驗證，見多裝置文件 |

循環和逐格已有 Android 延遲攝影產品的例子；同步比較已有 Android 動作分析產品的例子。[Video Delay Android](https://videodelay.app/video-delay-app-for-android/)、[Onform Android](https://play.google.com/store/apps/details?hl=en-US&id=com.app.OnForm)。針對本 App 的功能細節、優先順序與驗收條件是本次產品建議。

雙片比較應對齊共同事件，而不是一律同時從各自影片第 0 秒開始。Kinovea 官方文件以共同事件作時間原點，並支援連動播放與逐格。[同步設計參考](https://kinovea.readthedocs.io/en/latest/comparison/synchronization.html)。

遙控可參考 Video Delay 的鍵盤式控制器流程，但該指南展示的是 iPhone／iPad，不能當成 Android 配件相容性已驗證。[官方遙控指南](https://videodelay.app/game-controller-setup/)。

## 5. 可以加入或改善的設定

以下數字是建議起點，應由實際練習調整；不是硬體效能保證。

| 設定 | 建議選項／預設 | 現況與理由 |
| --- | --- | --- |
| 延遲快捷值 | 3／5／8／10 秒＋自訂；保留目前預設 5 秒 | 延遲已有，改善調整效率；依放下弓、轉頭看手機所需時間選擇 |
| 單箭保存範圍 | 以目前看到的影像時間點為中心，前 8 秒／後 3 秒作起點 | 現在不是固定「8 秒影片」；新設計應分清楚前後範圍與實際片長 |
| 保存後行為 | 回看／留在練習；沿用使用者選擇 | 兩個手動入口已有，補上手勢保存的偏好 |
| 回看結束行為 | 回到練習／停在片尾／循環；研究中不自動退出 | 現在有自動返回與互動後留在回放，增加明確偏好 |
| 重播次數 | 1／2／3 次；只在自動回看模式啟用 | 單箭重播可先從 2 次試用，不影響持續延遲模式 |
| 鏡頭與拍攝品質 | 前鏡頭預設；穩定／標準／細節預設 | 解析度、fps 與碼率依能力協商；高 fps 只在實測可用時出現 |
| 對焦與曝光 | 自動預設；點按對焦、曝光補償、支援時鎖定 | 某些前鏡頭固定焦距，不能提供無效的手動對焦按鈕 |
| 手勢開關與用途 | 張掌保存／比讚錄影可各自關閉、調整映射 | 現在映射與門檻寫在程式；顯示「容易／標準／較嚴格」，避免要求使用者理解模型分數 |
| 操作成功提示 | 畫面提示預設；可選提示音與震動 | 架遠時提示音有用；震動主要協助手持操作；暖機仍保留可讀秒數 |
| 收音 | 預設關閉，可選錄製環境聲 | 現在影片只有影像；若加入音訊，需處理音軌及同步，不只是加麥克風權限 |
| 小視窗與鏡像 | 小視窗顯示、四個角落、大小；鏡像偏好記住 | 顯示／收起與左右位置已有；新增更多位置與持久偏好，避免遮住手部 |
| 參考線 | 開關、可拖動位置、顏色與透明度，記住位置 | 線條已有；可依站位與構圖調整，不宣稱是姿勢判定工具 |
| 螢幕與操作區 | 自動方向預設；可鎖橫向／直向；操作區可收起 | 避免腳架轉動造成畫面變更；主影片維持完整構圖，不能再因加功能變小 |
| 儲存管理 | 剩餘空間、預估可錄時間、匯出品質 | 估算依實際碼率並標為約值；自動清理僅限暫存，不預設刪除保存影片 |
| 練習設定檔 | 記住上次選擇，可命名如「戶外側面」「室內正面」 | 將上述常用設定一起保存；不將固定秒數宣稱為普遍最佳 |

應先把常用選項分成「練習」「拍攝」「回放與保存」，進階項目收起。練習主畫面保留延遲秒數、錄影狀態、保存／標記與返回入口；畫線、量角、搜尋等功能放進研究畫面。新增功能不能擠壓最近修好的橫向影片區。

## 6. 保存範圍與標記必須先定義時間語意

目前程式取單箭範圍：`[觸發當下 − 延遲秒數 − 回溯秒數, 觸發當下]`，再選可用的已完成影片片段。因此預設延遲 5 秒、回溯 8 秒，請求範圍約為過去 13 秒，實際片長受準備程度與片段邊界影響。

新設定若採「目前看到的影像之前／之後」，參考點應來自播放器對應的來源拍攝時間。它不是自動辨識出的離弦瞬間；真正標記放箭時間，需由使用者在回放定位或另做事件偵測。

後段若尚未拍完，要顯示還需等待多久；不足的前段不能宣稱已完整保存。相簿標記、裁切、循環與全段錄影時間軸都必須共用同一套來源時間映射，避免看見某一箭卻跳到另一個時間點。

## 7. 畫質與穩定性的技術條件

目前 `ContinuousSegmentEncoder` 的編碼目標是 30 fps、8 Mbps；影像尺寸取決於實際收到的相機影像，沒有使用者選取的 HD／Full HD 拍攝設定。影像分析採只保留最新影像，且轉換有 JPEG／Bitmap 成本，所以「編碼目標 30 fps」不代表每秒一定捕捉到 30 張不同影像。

0.25× 是播放變慢，不能補回沒有拍到的影格。Android 官方區分高 fps 原始影片與已重編碼的慢動作影片，並要求查詢個別鏡頭支援的解析度與高速度能力。[CameraX 高速度錄影說明](https://developer.android.com/blog/posts/high-speed-capture-and-slow-motion-video-with-camera-x-1-5?hl=en)。

目前 App 使用自己的連續 MediaCodec 管線，不能直接把官方 Recorder 的高速度 API 當成現有功能開關。增加解析度或 fps 前，要同時測試延遲觀看、手勢、保存、全段錄影、橫直向與前背景恢復；影片中還要實查影格時間戳、掉格與片段交界。

畫質模式切換宜在停止並保存當前錄影後套用，明示重新準備的秒數。已保存片段不可被重新設定覆蓋。過熱時如果需要降低品質，應告知並完成當前錄影片段，避免在同一個 MP4 中悄悄混入不相容的影像格式。

中斷復原需要另外設計。`ContinuousRecordingSession` 目前保持一個 MP4 muxer 到停止時才完成，且暫存檔放在 cache；沒有系統結束程序後的復原索引。新增此功能應使用持久保存的已完成片段與索引，而不是只在下次啟動搜尋未完成 MP4。

## 8. 暫時不優先增加

- 手機上預設多路延遲分割畫面：與「橫向影片要夠大」的需求衝突；進階需求再提供。
- 延遲直接擴至數分鐘：目前立即看動作較需要合適的 5～10 秒和回看工具；較長延遲增加緩衝資源，需要另驗證。
- AI 自動姿勢評分：手部、弓具遮擋、拍攝角度與平面投影會影響判讀；先做好可人工檢查的影片。
- 箭著點、計分、社群、強制登入：不是這次已確認的兩個主要任務；有需求證據再排。
- 切到桌面仍持續拍攝：不是單一開關，涉及背景相機與服務設計。現階段保留清楚的前景拍攝、保存與返回準備流程。

## 9. 建議交付次序與驗收

1. **連續練習**：手勢保存偏好、預設只保存、觀看與錄影繼續，保留清楚結果與重試。
2. **事件與感受**：固定保存事件、來源時間、受保護片段與短語音，建立標記／收藏的資料基礎。
3. **回放研究**：A–B 循環、放大、標記與練習分組；精準逐格獨立驗證，不阻塞其他研究工具。
4. **多裝置一拍一看**：同 Wi-Fi／熱點、遠端觀看與控制、斷線核對、原檔收集。可行性原型提早做，正式版共用事件與時間基礎。
5. **組間整理與分析**：有上限的近期暫存、區段分享、練習目標與回顧、動作階段時間，按依賴分小版。
6. **獨立擴充**：每組多角度收集、即時雙角度、教練註解、跨平台各自估工。高 fps、聲音事件與 AI 另作能力驗證。

詳細範圍、工作量與關卡見 PM 文件；模組、時間／檔案保護、資料與指令契約見 SA 文件。

研究功能的建議驗收：能停在需要研究的真實影格、前後逐格不跳格；A–B 循環跨片段仍正確；縮放還原後完整動作入鏡；標記回到原本看到的一箭；裁切輸出實際可播放，原片保留。

拍攝功能的建議驗收：在使用者裝置上延遲＋錄影至少 30 分鐘，抽查前中後段與掉格；轉向、切鏡頭、回桌面與返回狀態可理解；空間不足時保存結果清楚。中斷復原需另外用強制結束程序測試，不能用一般切到桌面測試代替。

以上是待執行的驗收目標，不是測試通過紀錄。
