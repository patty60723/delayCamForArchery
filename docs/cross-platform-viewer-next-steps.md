# 多裝置下一步：Android、iPhone／iPad、電腦一起考量

2026-10-12，使用者補充第二台觀看端希望各平台都納入。這是後續安排，0.2.3 僅交付單機回放手勢，尚未具備多裝置連線。

## 產品範圍與角色

第一個拍攝端沿用使用者的 Android 手機。第二台可為 Android、iPhone／iPad 或電腦；觀看端預設不用相機、不辨識手勢，手勢由指定拍攝端提出一次指令。拍攝端看不到射手的手時，觀看端保留手動控制；另設手勢控制端屬後續驗證，不宣稱側面角度也一定識別。

配對在練習前完成，延遲觀看持續進行，當下控制保持可選。可同時有多個只讀觀看端，但先指定一個主要控制端，保存／開始／停止皆有指令 ID 和回覆，重送不反轉錄影或重複存同一箭。

## 各平台的首輪評估

| 觀看端 | 候選介面 | 必須驗證 |
| --- | --- | --- |
| Android | 瀏覽器共用觀看頁；現有 APK 的原生觀看角色也評估 | Chrome 連續播放、熱點連線；原生角色避免初始化觀看端相機／編碼器 |
| iPhone／iPad | Safari 瀏覽器觀看頁 | H.264／HLS 或適用的媒體管線、首次點擊開始、playsinline、橫向滿版、切背景／鎖屏後恢復 |
| 電腦 | Chrome／Edge／Safari 瀏覽器觀看頁 | 編碼支援、滑鼠／鍵盤控制、視窗縮放、多觀看端的來源時間與狀態一致 |

Android APK 只安裝在 Android。瀏覽器頁是候選共用觀看介面，不能在尚未驗證傳輸格式時承諾已能跨平台。各端共用產品行為、指令格式與來源時間，播放器適配可依平台不同。

## SA 原型工作包

1. **共用協定**：配對 session、裝置角色、主要控制者、來源 epoch、片段／畫格識別、codec 描述、來源時間、指令 ID、保存位置與狀態。先定義清楚哪些動作作用於觀看端、哪些送回拍攝端。
2. **媒體相容性關卡**：使用現有相機的已完成片段測瀏覽器。現有 MP4 分段重設相對 PTS，需要評估重封裝／連續時間軸與平台支援；不是只提供檔案 URL 就已完成無縫延遲播放。比較可行的分段 HLS／fMP4 與低延遲傳輸方案，量測實際等待與 CPU；沿用單一相機輸入，檢查是否需要額外編碼與其負載。
3. **共用觀看頁與 Android 適配**：配對 → 點擊開始觀看 → 延遲暖機／準備狀態 → 滿版影片 → 可收起控制；保存結果清楚顯示在哪一台，不每箭要求確認。Android 原生觀看若採用，也連相同協定與來源時間。
4. **三平台驗收矩陣**：在 Android Chrome、iPhone／iPad Safari、電腦瀏覽器測同一流程。測同 Wi-Fi／實際手機熱點、連續片段、回放／返回、斷線／重連、背景恢復、手動控制及一個指定手勢辨識端；錄影仍在拍攝端前景持續。
5. **決定正式交付**：依相容性、端到端延遲與長時間負載選媒體方式，再接完整保存／原檔收集。觀看端顯示的目標延遲包含傳輸等待，避免拍攝端與觀看端各加一遍延遲；設定低於實際能力時顯示可用範圍。

原型的通過條件是三類觀看端都能開始觀看、顯示可解釋的來源延遲／狀態、連續播放及執行不重複的指令；不是先完成三套獨立原生 App。尚未指定各裝置型號／瀏覽器版本，不設定未驗證的最小延遲或交付日期。

## 已配對裝置與快速重連

依使用者補充，把「記住已連線裝置」納入首輪連線原型，而非每次練習重新配對。

第一次完成配對後，保存裝置名稱、永久 peerId、身分指紋、配對授權／權限、發現服務識別及上次成功端點。IP 只是暫存連線提示，不能作裝置身分；新連線重新驗證已配對身分，避免 DHCP 改 IP 後連错裝置。更新 App 保留記錄；重新安裝、授權撤回或身分金鑰改變時清楚要求重新配對。

| 狀態 | 使用者看到／可做 |
| --- | --- |
| 已找到已配對裝置 | 顯示名稱與「連線」，一次操作恢復觀看 |
| 同網路連線中斷 | 顯示重連，有限退避重試，重新核對來源 epoch／真實錄影狀態 |
| 裝置未開啟或換網路 | 保留記錄，提示拍攝端開啟 App／確認同網路，提供重新搜尋與 QR Code 備援 |
| 配對授權失效 | 顯示「需重新配對」，不使用舊授權猜測成功 |

Android 原生候選使用 NSD／mDNS 發現已知服務，IP 改變後仍按 peerId 和身分指紋核對。瀏覽器先評估固定觀看入口／可解析的主機名稱、書籤或捷徑與站點配對記錄；瀏覽器腳本的區網搜尋與跨 origin 儲存有範圍限制，必須在 Chrome／Safari 實測。入口失效時可掃新的 QR Code 找到端點，授權是否可沿用依穩定來源與憑證方案驗證，不能先宣稱每個瀏覽器都可無感重連。

提供「忘記裝置／移除配對」，拍攝端也能撤銷授權。快速連線只恢復配對連線與觀看，取得拍攝端當下狀態；控制依目前授權與控制者核對，不回放上次開始／停止指令。原型驗收加入關閉重開 App、DHCP／IP 改變、網路切換、短暫斷線、授權撤銷、更新保留與兩個觀看端同時再連。

SA 可先以 KnownPeerRegistry（原生用 DataStore／安全金鑰儲存，瀏覽器依來源儲存策略）與 PeerDiscovery／PeerSession 分責，不以一次拍攝的 capture session 當永久裝置 ID。配對狀態與錄影狀態各自擁有；同一 requestId 重送仍只執行一次。

## 與目前排程的關係

1. 安裝 0.2.3 確認真實手勢站位與回放控制。
2. 優先驗證單機回放返回的安全緩衝恢復，縮短完整暖機等待。
3. 同時設計跨平台協定與上述媒體原型；依三平台關卡選實作，正式多裝置保存仍依 PM／SA 的事件與來源保護基礎交付。
