# 0.2.9 測試13·箭影：真正的取景與存檔比例

使用者確認將「取景比例：4:3／16:9」和「觀看方式：完整／滿版」分開。直拿分別為3:4／9:16。取景會影響新影格與新存檔；觀看滿版只依影片視窗再裁邊。預設4:3並保留之前觀看偏好，不重編舊影片。

## 實作

- MainActivity／Preview 維持4:3來源與一個相機連接。FrameCanvas 在固定編碼畫布內中心裁切新影格，沒有每影格建立額外Bitmap。GestureEngine仍辨識原始相機影格。即時窗中心填滿同一比例。
- 編碼器第一影格選偶數且精確比例尺寸，後續變更／旋轉不重設 MediaCodec。FrameShapeTimeline 記錄真正裁切後的影像比例，延遲／私有回放沿用有效畫面比例。
- 設定更新不清緩衝、不暖機；新比率到延遲畫面有原本設定秒數的等待。整段錄影期間比例停用，ViewModel亦阻擋；錄影固定開始比例／方向，旋轉保留來源於同一畫布。
- 必要的匯出正規化使用 Media3 Transformer＋單一動態 MatrixTransformation；用來源時間範圍去除已知編碼黑邊，再 FIT 到固定輸出比例，不拉伸。不需要轉換就沿用原本快速mux。需要轉換時保存較久，SAVING持續，30秒無輸出進度由Transformer回報失敗。
- 影片真正寫完MediaStore才成功；轉換失敗不寫假成功。整段來源與比例範圍保留供重試，單箭保護副本沿用既有重試。
- 新保存影片metadata改記正規化後的畫布比例，避免播放器再次移除黑邊；相簿標準播放器也能讀到正確比例。
- DataStore收集會忽略未完成最新寫入前的舊值，避免連續選擇後先跳回上一個選項。

版本code13、0.2.9-fast-return-test、名稱測試13·箭影；沿用 com.archery.delaycam.fastresume 與原簽章。code12保留給未交付的多裝置原型。PR6保持草稿，仍需手機長時間使用確認。

## 驗證

加入4:3／16:9尺寸與方向單元測試、Canvas真實像素裁切、真正編碼MP4的16:9與匯出，以及去除內部黑邊／保留邊界顏色／不同方向輸出的Media3測試。原本旋轉測試擴充比例保存、錄影中禁用與防繞過，並確認保留同相機／編碼器／緩衝。完整驗證已完成，見下方證據。

正規化只使用一個同時處理輸出尺寸與內容比例的變換，避免多個矩陣效果逐步裁切而遺失畫面。原生測試確認輸出左右邊緣確實有影像，且上下彩色邊界仍保留。

暖機期間若尚無相機影格即開始錄影，方向保持未定，改由第一段實際來源（未知混合比例時使用真正編碼尺寸）決定，不採用UI的預設直向。後續旋轉仍固定開始格式；原生測試核對第一段與後續方向改變。


取景設定只影響之後拍攝的內容；不把切換前的延遲／回溯來源當成新比例。單箭跨比例或方向時，輸出固定第一段來源的比例／方向，不拉伸舊內容；整段錄影依開始拍攝時的方向固定。若剛切換就保存回溯，可能仍包含舊比例。

影片需正規化時會使用保存階段的轉碼資源，可能增加保存時間；已符合輸出尺寸的資料直接沿用，不改檔案內容。不增加第二個相機串流。Pixel 的長時間錄影、發熱與轉碼速度仍需實機確認。
