# 當下回看：返回、變速與重播手勢提案

制定日期：2026-10-12。分析基準：已合併 0.2.2（PR #4）。使用者希望五指進入回放後，不走到手機旁也能提早返回、變快／變慢及重播。本文件是規劃，以下控制尚未加入 APK；手勢辨識效果仍待實機驗證。

## 1. PM：保留熟悉的流程

主要使用時機是放箭後當下與組間。延遲畫面仍可零操作觀看；使用者主動進入回放後，才開放研究控制。練習頁五指維持現行「保存並回看」，手動「只保存」保留；未經另行選擇，不把現有使用者的五指預設改成只保存。

| 需求 | 回放頁候選手勢 | 執行結果 | 其他頁面 |
| --- | --- | --- | --- |
| 提早返回 | 拇指朝下 Thumb_Down | 回到延遲練習；繼續保存與原本整段錄影 | LIVE 不執行此動作 |
| 變快 | 食指朝上 Pointing_Up | 往快一檔：0.25× → 0.5× → 1× | LIVE 不調整延遲速度 |
| 變慢 | V 手勢 Victory | 往慢一檔：1× → 0.5× → 0.25× | LIVE 不調整延遲速度 |
| 重播 | 五指張開 Open_Palm | 同一支回放從頭播放，保留當前速度與鏡像 | LIVE 仍保存並回看 |

比讚 Thumb_Up 保留既有開始／停止整段錄影，不挪作播放控制。握拳容易與拿弓的自然姿勢重疊，不列為第一版返回或重播手勢。上述名稱是 MediaPipe 內建候選類別，能分類不代表在射箭站位已可可靠使用。

第一版變快上限為既有 1×，指從慢動作回到正常速度；不先增加 1.5×／2×。到上、下限再比手勢時顯示「已是最快 1×」／「已是最慢 0.25×」，不循環跳到另一端。重播不另存一份影片，也不重新取一段延遲影像。

## 2. 回放結束與射箭節奏

建議第一輪未操作的回放播完後，保留最後畫格約 2 秒，顯示「2 秒後返回練習」，讓使用者有機會五指重播；這是待確認的流程預設，尚未變更現有自動返回。拇指朝下可在播放途中或倒數期間直接返回。若使用者已變速或重播，沿用現有主動研究規則：留在回放，直到明確返回。

回放本身不要求每箭操作；新增手勢是進入回看後的可選控制。教學放在操作說明／初次介紹，影片上只保留當前速度及短促的「已重播」「返回練習」回饋，不新增常駐四排教學、不跳確認對話框。提示音可選，不以手機震動作遠距離的唯一回饋。手動返回、速度按鈕保留，並補「重播」入口，皆使用同一指令路徑。

「返回上一頁」在此明確定義為返回延遲練習，與任意 navigation pop 分開。相簿播放屬事後研究，第一版維持觸控；不在相簿、設定或 App 背景接受練習手勢。

## 3. 現有程式證據與可行性

| 現況 | 對實作的意義 |
| --- | --- |
| GestureEngine 使用同一 MediaPipe LIVE_STREAM，目前只處理 Open_Palm 與 Thumb_Up；沒有限制模型只能回傳這兩類 | 可加入候選類別判定，不必再載入另一套模型或另開相機 |
| locked 在 SAVING／REPLAY 鎖住張掌保存，錄影手勢仍可處理 | 需要依畫面路由分配指令，不可只解除 locked，否則可能重複存檔 |
| GestureLatch 穩定 350 ms、冷卻 3 秒、保持只觸發一次；目前單次 unmatched 就可重新啟用 | 新回放指令需要穩定放手判斷，不能把單幀辨識失敗當成已放下手 |
| skipReplay() 與手動「返回練習」已存在 | 手勢可共用返回流程，匯出中仍保留 snapshot，等待保存作業完成才清理 |
| PlaybackControls 已有 0.25×／0.5×／1×；markReplayInteraction() 可抑制自動返回 | 變速可共用既有播放器能力與研究停留政策 |
| replayPlayer 使用受保護片段清單，結束後尚未返回時仍可 seek | 重播可 seekTo(0, 0) 並 play，不能再次呼叫 triggerSave() |
| onReplayFinished() 呼叫 resetDelayedPlayback()；該方法清空 segmentBuffer 並重新倒數 | 快速返回頁面不等於延遲影片即刻就緒，須獨立驗證返回緩衝改善 |

程式設計有讓回放時繼續辨識的入口，但新功能仍須驗證實際回放畫面下有持續的即時相機畫格。辨識來源必須是現場相機，不能對回放影片的人手再下指令。

## 4. SA：場景、指令與播放器共用

先增加明確的本機指令：ReturnToPractice、ReplayCurrentClip、IncreaseReplaySpeed、DecreaseReplaySpeed。練習原有保存與錄影指令保留。辨識層負責手勢候選、信心值與穩定保持；互動政策依 LIVE／REPLAY／SAVING／其他頁面決定允許的動作；PlaybackSessionController 擁有播放與結束政策。

手勢、觸控都進同一入口，避免兩套速度、重播與自動返回邏輯。速度顯示讀播放器的同一狀態，沿用目前速度偏好來源；延遲播放器不跟著回放變速。返回與重播不切換整段錄影、不取消正在執行的單箭匯出。

所有 Media3 操作在主執行緒執行。接受命令前重查前景、畫面、回放識別與媒體是否可用；辨識結果帶入當時場景版本，切頁、換影片或切背景後丟棄舊結果。改速或重播先標記使用者互動、取消自動返回倒數，再操作播放器；倒數也核對同一回放版本，避免舊 callback 關掉剛重播的影片。

SAVING 且尚未建立回放時不處理播放指令；已有可用回放、僅匯出仍在 SAVING 時，播放控制仍可用。片段未就緒或播放錯誤時給短提示與既有重試／返回入口，不宣稱重播成功。

## 5. 手勢觸發保護

- 每次保持手勢只執行一次；重播與變速不因保持數秒而反覆觸發。
- 從 LIVE 五指進 REPLAY 後，先等待真正放手，不把同一張掌重新解釋為重播。REPLAY 返回 LIVE 亦同。
- 原型起點：新回放手勢穩定保持約 0.6 秒，非控制姿勢／手離開持續約 0.3 秒後重新啟用，回放動作冷卻約 0.8–1 秒；信心門檻依每類實測調整。這些不是已驗證的辨識參數。
- 原有 LIVE 保存、比讚錄影的門檻與 3 秒冷卻不一併降低；不為了變速變靈敏而增加誤停錄影。
- 返回不被其他播放命令的共用長冷卻擋住；同一返回姿勢仍須穩定保持與放手，避免偶然一幀直接退出。
- 不預設 App 已辨識出拉弓／放箭階段；頁面限制與保持判定不能替代實際自然動作誤觸測試。

## 6. 快速返回延遲畫面的原型

目前返回會清掉舊延遲播放與緩衝，暖機倒數重新開始。不得只刪掉 reset 或直接播放暫停的位置：回放期間累積的隊列可能過舊，循環檔案也可能被覆寫。

建議另做 resumeLiveFromBuffer 原型：在同一前景相機 session、延遲設定未改且片段連續可用時，從目前來源時間減設定延遲的位置重建有限的有效播放清單，接上後續片段。保存／播放所用片段要有有效版本及引用保護，清掉過期 callback，不沿用暫停前的舊位置。

返回頁面與首畫格就緒分開呈現；已有完整緩衝時只等首畫格，不額外強制再等完整延遲秒數。若切背景、來源 session 改變、片段缺失、設定改變或播放錯誤，仍走既有安全重建與真實暖機提示。保留先前黑屏修正中的 reset 同步清理規則，不以縮短等待為由取消復原機制。

先量測現況，再驗證原型可否把正常回放返回的等待從完整 delay 縮至重新呈現首畫格的時間；不能先保證零等待。相機 Surface 的持續供應也要驗證，必要時把唯一的 Surface host 擁有者移到導航外，避免重建第二套相機或在回放時失去即時畫格。

## 7. 交付順序與驗收

| 順序 | 可交付項目 | 關卡 |
| --- | --- | --- |
| 0 | 回放期間的即時辨識與返回時間原型 | 確認相機畫格持續；量測與保護延遲恢復，不重新引入黑屏／舊片段 |
| 1 | 返回與重播手勢、手動重播、場景防重複 | 五指跨頁只存一次；重播同一影片且不重複保存；返回不停止錄影、不丟匯出 |
| 2 | 加快／放慢候選手勢與短回饋 | 速度逐檔、邊界不循環、與手動控制一致；重播保留速度與鏡像 |
| 3 | 回放結束短停留與手機交付 | 倒數可被研究動作取消；手勢、結束、背景與保存競態測試通過 |

在同一次需求交付中完成三類控制，但先驗證依賴、分小步實作。正常返回不必完整重新暖機是重要產品目標；若原型未達成，交付說明必須標明實際等待，不能把手勢返回與即刻可觀看混為一談。

自動檢查至少涵蓋場景路由、持續保持、單幀掉辨識、放手、舊結果、速度邊界、跨片段重播、播完競態、返回中保存與前背景復原。實機以使用者腳架站位測每個候選手勢 20 次，原型目標至少接受 18 次，另測持弓／拉弓／收勢的自然動作、護具、左右手、逆光與錄影負載；這是驗收目標，不是已達到的成功率。

此提案優先於原先預设改成只保存的第 1 版方向；只保存維持可選。多裝置、語音、逐格與 A–B 循環仍依原本里程碑安排，不併入此次手勢控制。
