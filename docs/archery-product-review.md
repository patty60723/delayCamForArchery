# 射箭 Delay Camera：PM 功能完整性與產品建議

評估日期：2026-10-11。程式基準：已合併版本 `b5f9dc53f91a73bb4b9d8e2f6223cddb778e5dfe`。

使用者確認的情境：「自己架手機，放箭後立刻看動作；但也會錄影下來事後研究」。因此，即時回饋與保存後研究都屬於核心需求，教練協作與其他射箭工具則是後續擴展。

本文件是產品分析與建議，沒有修改 App 或提交 GitHub。依程式與使用者回饋判斷，沒有進行市場訪談、現場操作或效能量測；提案與驗收目標均不代表已實作或已通過。

## 1. 產品定位與完整性判斷

建議定位為「一個人也能架好手機，看剛才的一箭，並留下值得研究的動作」。使用者的成功條件是練習後知道要觀察哪個動作、能繼續下一箭，以及事後找得到可研究的影片。

目前的核心功能已構成可用的 MVP：延遲鏡子、即時取景、手勢與手動保存、慢動作、連續錄影、相簿與本機分享都有。使用者也回報近期黑屏與返回前景凍結修正後看起來正常。

但若以完整的一次練習和事後研究衡量，仍需補足三件事：觀看內容與狀態清楚、錄影保存可靠、研究動作的控制與整理足夠。近期的生命週期測試與使用者回報不能替代長時間錄影、檔案可播放性及戶外操作驗證。

不需要為了「完整」立刻加入計分、箭著點辨識、社群或課程。這些功能對部分射箭使用者可能有價值，但不是目前兩個主要任務的必要條件。

## 2. 依練習任務盤點現況

| 練習任務 | 已確認的功能 | 主要缺口與影響 | 判斷 |

## 3. 下一版先完成的 P0

P0 指影響看清動作、可信狀態或影片保存的事項。以下是建議的完成條件，不是現況測試結果。

### P0-A：建立可靠的觀看與錄影狀態

- 練習畫面預設完整呈現影片，保留「填滿」為選項。構圖檢查應涵蓋持弓手、拉弓手、手肘與使用者要研究的身體部位。
- 明示「延遲設定 5 秒／準備中／已就緒」，小視窗標「即時」。設定值不能被當成已量測的實際延遲保證。
- 量測實際畫面延遲與漂移，讓設定套用、重新準備和異常恢復有一致行為；不要只更改數字而讓既有佇列造成不可理解的時間差。
- LIVE 和即時回放都顯示全程錄影狀態，並有明確停止入口；仍在錄影時，切畫面不能把控制藏起來。
- 在練習期間明確管理螢幕常亮，再用裝置驗證。程式未見明確常亮設定，尚不能斷言實機必然休眠。

### P0-B：決定背景與長時間錄影的保存政策

短期建議採「只在前景拍攝」：切到桌面時停止並保存當前錄影段；回來提示「上一段已保存，錄影已停止」，提供明確的「繼續錄影」。延遲畫面另行重新準備。儲存失敗必須呈現失敗，不能先宣告成功。

這樣可以避免把桌面時間算進有效錄影，也讓使用者知道檔案已完成。停止時應處理或清楚交代尚未完成的尾段，不能把按下停止等同於最後一秒必定已存入。

較完整的後續方案是持續保存可獨立恢復的分段，將多段歸為同一練習，並在 App 重開時提供復原。這需要專門的媒體儲存設計；目前程式只在停止後完成全段匯出，不能承諾系統終止後能救回全部內容，也不能承諾背景持續拍攝。

保存狀態分清楚「儲存中／已保存／失敗」。長片與單箭輸出都應實際打開驗證片長、時間序、尾段、橫直向與可播放性。低空間或真實錄影錯誤發生時才顯示可操作的提示，不把硬體數據常駐在主畫面。

### P0-C：避免手勢誤觸與檔案誤刪

- 一次手勢只發出一次指令，手放下或離開匹配狀態後才重新啟用。目前冷卻時間本身不能阻止持續比讚再次切換錄影。
- 手勢依頁面啟用；相簿和設定不應因辨識到手而跳進回放。回放中若允許切換全程錄影，就必須同步呈現狀態與手動停止入口。
- 提供手勢開關，保留手動操作，並給予看得見的觸發回饋。戴護具、背光、距離較遠時的辨識效果需現場驗證。
- 刪除影片要確認或可復原；重要保存失敗不能只用短暫提示。

## 4. 增加哪些功能：P1 的兩條完整流程

### P1-A：即時觀看不必被保存打斷

保留目前「存檔並回看」，因為每箭檢查對單人練習有價值。另加「只保存，繼續練習」，可設為偏好；先延續目前預設，再觀察使用者在每箭檢查與連續射一組時的選擇。

不必每次開 App 都先選模式。正常流程直接進入取景與延遲觀看，只有需要更改保存後行為時才調整。

延遲提供 3／5／8／10 秒快捷值及自訂，讓使用者依放下弓、轉頭看手機的時間選擇。小視窗能收起／換角落，參考線可以關閉；這些調整不應成為每次使用前的必要設定。

### P1-B：保存後能有效研究動作

1. **即時與相簿回放共用操作**：播放／暫停、拖曳時間軸、0.25×／0.5×／1×、一致的影片鏡像選項。正在暫停檢查時不強制跳回練習。
2. **逐格與 A-B 循環**：反覆觀察放箭前後的同一段。先做常用控制，再補逐格精度與循環；需要核對來源時間戳和真實 fps。目前編碼設定 30 fps，降低播放速度不會增加原本沒有拍到的動作細節。
3. **長片時間點標記**：可標記「剛才看到的一箭」，事後直接跳到該處。標記應對應被觀看畫面的拍攝時間，不能直接用按下當下的時間，否則會受到延遲影響。
4. **練習分組與收藏**：依日期／練習時段整理，辨認單箭片段和整段錄影；提供收藏與簡短備註，如「延伸」「拉弓手」。不先做複雜標籤管理。
5. **輕量裁切與分享**：保留系統分享，長片可選研究區段再分享，不必把整段練習傳給教練。

前鏡頭符合「螢幕朝向自己，也拍得到自己」的用法，應保留。後鏡頭選擇可作 P1 後段的選項，供較高品質錄影或旁人協助構圖；加入後需解決自己看不到螢幕與取景的問題，不預設強制改用後鏡頭。

## 5. 可以減少、收起或改名的功能

| 調整 | 原因與保留方式 |
| --- | --- |
| 收起常駐手勢教學 | 首次教學與幫助入口保留；練習時將空間留給動作、延遲和 REC |
| 降低手勢模型狀態的視覺權重 | 使用者先需要知道能否保存、是否在錄影；手勢失效時提供手動替代提示 |
| 將「慣用手」改為「即時小視窗位置」 | 現況只控制視窗位置，不代表射箭持弓側或姿勢判定；直接命名更容易理解 |
| 將「下載／分享」改為「分享影片」 | 檔案已在本機，現有功能是呼叫系統分享；另存應明示不同目的 |
| 把進階說明與自訂秒數移到次要層 | 快捷值先呈現；保留完整範圍，避免縮減實際可用情境 |
| 整合兩套回放控制 | 保留即時回到練習的捷徑，同時讓暫停、速度與鏡像一致 |

參考線保留為構圖工具，但不要宣稱能判定姿勢正確。即時小視窗保留為架手機的輔助，而非強制永久遮在影片上。

## 6. P2：有需求與驗證後再擴展

- **兩片比較或教練註記**：適合進階研究，但先確認使用者如何對齊拉弓與放箭瞬間。
- **60／120 fps 拍攝**：需裝置能力、低光畫質、發熱及整條延遲／錄影管線驗證，並保留穩定模式。
- **實體或藍牙遙控**：先確認配件與協定支援；適用不方便走到手機或手勢不穩的情境。
- **投放大螢幕**：有團隊或教練觀看需求再做，需交代額外延遲。
- **AI 姿勢分析、箭著點與計分**：需拍攝條件與判讀效度驗證。暫不把這些放進下一版核心範圍。
- **雲端帳號、社群與複雜訓練計畫**：目前沒有需求證據，保持本機、直接開始練習即可。

## 7. 建議版次與驗收

以可驗證的成果分批，不承諾尚未估工的交付日期。

| 版次 | 交付重點 | 建議驗收目標 |
| --- | --- | --- |
| A：可信的練習與錄影 | P0 取景、時間標籤、前背景錄影政策、手勢、保存狀態、刪除保護 | 30 分鐘延遲觀看並同時錄影；抽看前中後段；反覆進出桌面確認狀態與檔案；同一比讚保持 10 秒只觸發一次 |
| B：當下與事後研究 | 只保存、共用播放控制、逐格／循環、標記、分組收藏 | 同一箭可保存後繼續、也可暫停重看；從長片標記找回剛才的動作；輸出可分享區段 |
| C：按需求擴充 | 兩片比較、高 fps、遙控或教練流程 | 每項先定義實際練習任務與裝置條件，再決定是否做 |

其他必要驗收：用有可辨識時間的畫面量測設定與實際延遲；只看不碰時螢幕保持開啟；橫直向完整構圖；戶外亮度與觀看距離；護具和拿弓情境的誤觸；低空間保存失敗可理解；匯出影片在系統播放器可打開。這些是待執行測試，不是現有測試紀錄。

建議招募 5～8 位單人練習者，含初學與有經驗者，觀察架手機、放箭後觀看、保存單箭、錄完整輪與事後找片。記錄完成任務時間、走到手機的次數、錄影狀態判讀錯誤，以及能否找回同一箭。不要只問喜不喜歡介面；先看流程是否完成。

## 8. 與 UI／UX 建議的整合

另一位 agent 的獨立分析見 [archery-uiux-review.md](archery-uiux-review.md)。兩份報告共同採用：影片優先、完整取景、延遲／即時／錄影標籤、保存結果清楚、即時回放與相簿操作一致。

UI 上可以保持錄影為次要按鈕；功能與可靠性上，整段錄影依使用者需求仍是核心。常用研究控制列 P1，兩片比較與自動分析列 P2。只保存入口屬 P1 的流程改善，P0 先避免錄影狀態誤導、手勢誤觸與重要影片遺失。

### 保存範圍的特別說明

預設延遲 5 秒、回溯 8 秒時，程式請求保存的範圍是「現在往前約 13 秒到現在」。它意在把延遲畫面所見的時間點及其前面的動作保留下來，實際輸出仍受到片段邊界、已完成的資料和暖機程度影響。

因此應改善文案和時間語意，並核對輸出，不應只把畫面改成「保證保存 13 秒」。標記、裁切與影片片長都應依實際捕捉與輸出結果呈現。
